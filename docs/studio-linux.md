# Linux에서 ZUKU Studio 실행

ZUKU Studio의 Linux 창은 GTK3와 WebKitGTK 4.1을 사용합니다. 기존 CLI와 같은 AgentCore, 프로젝트 권한, 인증 상태를 사용하며, 설치된 관리용 Node로 공통 Studio 연결 프로세스를 시작합니다. 게임 작업을 수행하는 별도 에이전트를 만들지 않습니다.

현재 소스의 Linux 실행 파일은 `studio/native/linux/build/zuku-studio`입니다. 일반 데스크톱 사용자로 실행하며 Node 22 이상이 필요합니다. Linux 데스크톱 세션과 GTK3·WebKitGTK 4.1 런타임이 없는 환경에서는 네이티브 창을 실행할 수 없습니다. 이번 x64 실행 파일의 시스템 요구는 glibc 2.34 이상이며, Node의 최소 시스템 요구와 별도로 충족해야 합니다. 설치본의 Linux 실행 파일은 `release/studio/linux/zuku-studio`이며, `release/runtime/bin/node` 하나로 CLI·Core·Studio를 실행합니다. 설치 표식과 공개 CLI 패키지를 같은 배포 폴더에서 확인합니다.

```sh
cd studio/native/linux
make
make check
./build/zuku-studio
```

개발 빌드에는 C11 컴파일러, `pkg-config`, GTK3·WebKitGTK 4.1·JavaScriptCoreGTK 4.1·GIO 개발 파일이 필요합니다. 다른 관리용 Node를 사용한다면 `make NODE_EXECUTABLE=/absolute/path/to/node`로 빌드할 수 있습니다. 개발 소스 실행에는 `--managed-node /absolute/path/to/node`를 지원합니다. 설치된 전체 Studio에서는 외부 Node 지정이 허용되지 않습니다. 화면에서 실행 경로나 명령 인수를 지정할 수는 없습니다.

프로젝트 열기는 운영체제의 폴더 선택 창에서 직접 승인합니다. 선택한 경로는 네이티브 연결 프로세스를 거쳐 공통 코어에 전달됩니다. 화면에는 프로젝트 이름과 불투명한 프로젝트 식별자만 반환합니다. 사용자 홈 전체와 인증 설정 폴더를 프로젝트로 선택할 수 없습니다.

웹 연결과 제공자 인증은 별도 네이티브 승인 창에서 처리합니다. 웹 연결 창은 `https://ai.zuzunza.com`의 요청을 표시하고 기본 선택은 거절입니다. 비밀 입력에는 가려진 입력란을 사용합니다. 기기 인증과 공식 인증 URL은 네이티브 창의 안내를 확인하고 승인하거나 취소합니다. 검증된 공식 URL의 인증 페이지는 네이티브 버튼을 직접 눌렀을 때 열립니다. 실험적 인증에는 주황색 `(exp!)` 표시가 붙습니다. 인증 입력, 로컬 절대 경로, 네이티브 승인 메시지는 게임 개발 화면에 전달하지 않습니다.

게임 미리보기는 공통 코어가 등록한 고정 스냅샷을 별도 WebKit 화면에 표시합니다. 네이티브 연결 기능과 인증 창에 접근할 수 없고, 화면을 열기 전에 WebKit 차단 규칙을 적용하여 스냅샷 전용 로컬 주소의 경로 밖으로 이동하거나 다른 자원을 요청하지 못하도록 합니다. 저장소·파일 선택·권한 요청·새 창도 허용하지 않습니다. 화면에서 미리보기 주소를 임의로 입력하는 기능은 없습니다.

네이티브 창은 설치 파일과 실행 파일의 소유권, 쓰기 권한, 실제 경로를 확인합니다. 신뢰하는 화면 파일만 제한된 목록으로 제공하고, 공통 프로토콜의 요청·이벤트 검증을 사용합니다. 구독을 해제하거나 창을 닫아도 진행 중인 공통 코어 작업을 취소하는 요청으로 바꾸지 않습니다. 브라우저 샌드박스를 활성화하며 관리자 사용자로 네이티브 화면을 시작하지 않습니다.

확인된 범위는 실제 C 컴파일, 공통 프로토콜 31개 검증 그룹, 미리보기 경로 경계 10개, 합성 C·Node 연결 3건, Linux 브리지 회귀 시험 8건입니다. 회귀 시험은 실제 C 요청 검증과 공통 연결 스크립트를 사용하고, 공백·한글이 있는 설치 경로와 관리 런타임 배치를 확인합니다.

보통 사용자 권한의 Weston·Xwayland 화면에서 현재 렌더러와 실제 Studio 연결 프로세스·AgentCore를 함께 실행했습니다. 실제 GTK 폴더 선택, 파일 읽기, 세션 생성, 이벤트 수신과 구독 해제, 화면의 미리보기 버튼을 통한 게임 캔버스 표시와 연결 기능 격리를 확인했습니다. 비밀 입력 마스킹·승인·연결 창은 합성 요청으로 검증했으며 실제 제공자 로그인·추론·게시는 실행하지 않았습니다. 별도의 합성 HTTP 서버를 사용한 실제 WebKit 시험에서는 허용된 요청 2건이 도착하고 경계 밖 이미지 요청 7건은 도착하지 않았습니다. 브라우저 샌드박스를 해제하지 않았습니다. Windows·macOS의 네이티브 실행 결과를 이 Linux 시험으로 대신하지 않습니다.

초기 Linux 셸은 기존 동결 구현의 소스 해시를 확인한 뒤 공통 프로토콜과 현재 화면에 맞게 수정했습니다. 이전 구현의 제한된 화면과 운영 서비스 파일은 포함하지 않았습니다. 공개 패키지에서는 이 저장소의 라이선스와 패키징 정책을 따릅니다.
